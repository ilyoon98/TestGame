# HEX / 전장

휴대폰으로 명령하고 TV 전광판으로 동시에 해결하는 2–6인 턴제 포격 파티게임입니다.

## 실행

```powershell
npm ci
npm start
```

호스트는 `http://localhost:4173`으로 접속합니다. 같은 Wi-Fi의 참가자는 홈 화면에 표시되는
`http://<호스트-IP>:4173` 주소로 접속합니다. Windows 방화벽이 물으면 사설 네트워크에서 Node.js 접근을
허용해야 합니다.

> `index.html`을 파일 탐색기에서 더블클릭해 여는 방식으로는 동작하지 않습니다. 자산 경로(`/style.css` 등)와
> `/api` 호출이 모두 서버를 전제로 하기 때문입니다. 잘못 열면 안내 화면이 대신 뜹니다.

- 홈 화면에는 현재 참여 가능한 로컬 방이 자동으로 표시됩니다.
- 방을 만들면 로비에 참가 QR과 PC용 초대 링크가 함께 생성됩니다.
- QR 또는 `/join/<방 ID>` 초대 링크로 들어오면 초대받은 방이 목록 상단에 표시됩니다.
- 방 ID는 내부에서만 쓰이며 사용자가 코드를 직접 입력할 필요는 없습니다.

## 세 가지 화면

| 역할 | 기기 | 하는 일 |
|---|---|---|
| 플레이어 | 휴대폰 | 부대 선택 → 이동/공격 예약 → 턴 제출 |
| 전광판 | TV·큰 화면 | 공개 정보만 크게 중계. 명령은 못 내림 |
| 방장 | 아무 기기 | 전장 설정, 게임 시작, 추방, 종료 후 재대결 |

## 무엇이 공개되고 무엇이 숨겨지나

이 게임의 핵심은 안개전장입니다. 각자가 보는 것이 다릅니다.

- **플레이어**는 자기 부대와, 자기 부대 시야 안에 들어온 적만 봅니다.
- **사격한 부대와 피격된 부대는 그 턴 동안 모두에게 공개됩니다.** 쏘면 위치가 드러납니다.
- **전광판은 이 공개 집합만** 봅니다. 그래서 명령 단계에는 판이 비어 있는 것이 정상이고,
  포격이 시작되면 채워집니다. 전광판에 전부 보여주면 안개전장이 무너집니다.
- 한 번 본 적은 이후 **마지막 발견 위치**가 점선으로 남습니다.
- 포탄이 떨어진 칸에는 그 턴 동안 착탄 흔적(피해량·피격자)이 남습니다.

## 규칙

**부대** — 플레이어당 보병·포병·정찰 각 1기. 참가자가 2명을 넘을 때마다 최대 체력이 +2씩 오릅니다.

| 부대 | 체력 | 사거리 | 이동 | 시야 | 피해 보정 |
|---|---|---|---|---|---|
| 보병 | 38 | 1–2 | 1 | 1 | +0 |
| 포병 | 32 | 2–4 | 1 | 1 | +3 |
| 정찰 | 24 | 1–2 | 2 | 2 | −3 |

**턴 흐름** — 명령 준비 → 이동 → 공격 → 결과. 부대마다 이동 1회와 공격 1회를 예약할 수 있고,
모든 플레이어가 제출하면 동시에 해결됩니다. **부대가 전멸한 플레이어는 제출하지 않아도 턴이 진행됩니다.**

**지형** — 매 턴 새로 생성됩니다.

- 고지: 사거리 +1, 시야 +1, 이곳에서 쏘면 피해 +2
- 숲: 이 칸에 있는 목표가 받는 피해 −3
- 강: 이동 불가 / 다리: 통과 가능

**피해** — `max(1, d20 + 부대 보정 + 고지 보너스 − 숲 엄폐)`

**이동 충돌** — 두 부대가 같은 칸을 노리거나 이미 누가 서 있는 칸으로 가면, 해당 이동은 모두 취소되고
제자리에 남습니다.

**승패** — 생존자가 1명 이하가 되거나 턴 한도에 도달하면 종료. 점수는 `누적 피해 + 남은 총 체력`입니다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `server.js` | 규칙 엔진 · 상태 · HTTP API. 게임 판정은 전부 여기 |
| `index.html` | 세 화면(홈·로비·전장)의 뼈대 |
| `style.css` | 디자인 토큰과 전 화면 스타일 |
| `ui-kit.js` | 모션·토스트·모달·스켈레톤·고배율 캔버스 등 표현 레이어 |
| `app.js` | 홈·로비 화면과 서버 폴링 |
| `battle-ui-v4.js` | 전장 화면 렌더링과 조작 |
| `local-access.js` | 초대 링크 진입과 세션 복원 |

`ui-kit.js`는 [motion.dev](https://motion.dev)와 [anime.js](https://animejs.com)를 CDN에서 `defer`로 불러
쓰되, **둘 다 실패해도 CSS·WAAPI로 대체**됩니다. 인터넷 없는 LAN 환경에서도 UI가 그대로 동작합니다.

## 인터넷 배포

Render Blueprint를 만들 때 `prototypes/hex-war-lobby/render.yaml`을 Blueprint 경로로 지정합니다.
Docker로 실행할 때는 이 폴더에서 `docker build -t hex-war-lobby .`와 `docker run --rm -p 4173:4173 hex-war-lobby`를 실행합니다.
Render로 배포하면 하나의 공통
HTTPS URL이 만들어집니다. 방 상태는 `rooms-state.json`에 저장되므로 영구 디스크가 없는 무료 인스턴스에서는
재시작 시 초기화될 수 있습니다. 실제 운영에서는 Render 영구 디스크 또는 Redis/데이터베이스를 권장합니다.
