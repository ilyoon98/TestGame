# Steam 일일 게임 브리핑

Steam만 조사하고 한국어로 보고한다. 기본 지역은 대한민국, 통화는 KRW, 시간대는 Asia/Seoul이다. 사용자가 지정한 장르·예산·기간이 있으면 우선 적용한다. 계정 로그인이나 API 키는 필수가 아니다. 폴더 이름 `steam-epic-daily-brief`는 기존 호출·자동화 호환을 위해 유지하지만 Epic은 현재 조사 대상이 아니다.

## 정기 보고와 장르

**현재 정기 실행은 매일 오전 9시(KST)에 선택 질문 없이 Steam을 조사하고 장르별 보고서를 바로 제공한다.** 수동 조사는 이번 요청에 명시한 장르를 적용하고 미지정이면 같은 장르별 구성을 사용한다. 과거 RPG나 덱빌딩 선택으로 정기 보고 범위를 제한하지 않는다.

장르·플레이 유형은 RPG, 액션, 어드벤처, 로그라이크·로그라이트, 전략, 시뮬레이션·경영, 생존·제작, 공포, 퍼즐, 플랫포머·메트로배니아, 스포츠·레이싱, 리듬·음악, 방치형, 증분, 자동화·공장, 타워 디펜스, 도시 건설, 덱빌딩, 오토배틀러의 19개로 묶는다. 각 장르 안에서 무료 소장 → 신작·예정작 → 할인 순으로 정리한다. 장르마다 신작 최대 3개와 할인 최대 3개를 각각 별도로 선정하고, 확인된 무료 소장은 별도로 포함한다. 인디 게임을 우선 보강한다. 후보가 충분하면 각 장르의 신작·할인 각각에서 인디를 2개 이상 우선 검토하되 적합한 후보가 부족하면 억지로 채우지 않는다. 인디 여부는 Steam 공식 장르 인디(ID 23) 또는 실제 사용자 태그 인디(ID 492)로 확인하고 제작 규모를 추측하지 않는다. 같은 게임은 대표 장르에 한 번만 싣고 나머지 장르는 태그로 적는다. 여러 혜택이 겹쳐도 한 행에 가격·출시 상태·배포 유형을 함께 적어 중복을 줄인다. 해당 없는 장르는 짧게 표시하고, 접근 실패는 해당 없음과 구분한다. 모든 장르에 게임을 억지로 채우지 않는다.

사용자가 따로 장르를 고르겠다고 요청할 때만 [복수 선택 화면](assets/genre-picker.html)을 사용한다. `visualize` 스킬을 읽고 현재 채팅의 쓰기 가능한 시각화 폴더에 새 이름으로 복사해 표시한다. 버튼을 여러 개 눌러 선택한 뒤 `선택한 장르로 조사`를 제출하면 해당 조사에 적용한다. 화면 표시나 단순 클릭만으로 조사를 시작하지 않는다. 이 수동 선택은 오전 9시의 전체 장르별 정기 보고 설정을 바꾸지 않는다.

선택 화면을 표시할 수 없으면 장르별 예/아니오 질문들을 묶어 복수 선택이 가능한 입력을 제공하거나 쉼표 입력을 안내한다. 단일 선택 질문 하나를 복수 선택 버튼이라고 부르지 않는다. 시각화의 후속 메시지 기능이 없으면 화면이 선택 결과를 채팅에 보낼 문장으로 제공한다.

- 자연어와 `장르: RPG`, `장르: 로그라이크, 전략 / 제외: 공포` 같은 입력을 모두 받는다. 장르 외에도 덱빌딩·자동 전투·방치형·협동 같은 플레이 방식이나 태그를 조건으로 사용할 수 있다.
- 여러 장르를 쉼표로 나열하면 하나 이상에 해당하는 게임을 찾는다(OR). `로그라이크이면서 덱빌딩`, `전략 중 턴제만`처럼 교집합을 요청하면 두 조건을 모두 만족해야 한다(AND). 제외 조건은 항상 우선한다.
- `장르 선택`, `어떤 장르를 고를 수 있어?` 요청에는 복수 선택 화면을 제공한다. 지원하지 않는 환경에서는 앞서 설명한 복수 응답 대안을 사용한다. 이미 장르를 지정하고 조사를 요청했다면 다시 묻지 말고 조사한다.
- 선택 조건은 기본적으로 **신작·할인·무료 배포 모두**에 적용한다. 사용자가 `무료 배포는 전체 장르로` 같은 예외를 지정하면 그 부분만 따르고 표에 범위를 표시한다. 결과가 없다고 임의로 다른 장르나 기간을 섞지 않는다.
- 장르는 공식 상품 페이지의 분류·태그·게임 설명으로 확인한다. 예를 들어 `로그라이크`는 Roguelike/Roguelite, `방치형`은 Idle/Idler, `증분`은 Incremental/인크리멘탈로 후보를 찾되 실제 플레이 설명을 확인한다. Steam 유저 태그만 근거면 `유저 태그 기준`이라고 밝힌다. 이름이나 상점의 신작 추천 위치만 보고 분류하지 않는다. 스토어마다 다른 장르 체계를 그대로 동일하다고 간주하지 않는다.
- 장르 선택 제출과 `오늘 RPG만 조사`는 이번 실행에만 적용한다. 이후 정기 실행은 전체 장르별 보고를 유지한다. 사용자가 정기 실행 방식을 명시적으로 바꿀 때만 기존 자동화를 갱신하고 일정·대상 채팅·다른 선호는 유지한다. 장르별 자동화를 새로 만들라는 요청이 없으면 기존 자동화를 수정한다.

일반 게임에 성적·노출 요소가 있는지는 Steam 사용자 태그 **선정적 콘텐츠(Sexual Content, 12095)·신체 노출(Nudity, 6650)**로 확인한다. `includeMature` 필드는 기존 호환을 위해 유지하고, 켜진 경우 왼쪽 장르 목록의 **성인 요소**에서 해당 일반 게임을 모아 볼 수 있다. 이 분류는 성인 전용 성적 콘텐츠 카탈로그와 다르며, 성인 전용 게임 추천 목록으로 소개하지 않는다. 일반 장르 후보 안에서 확인한 부수적 요소를 표시하는 용도다. 성인 전용 성적 콘텐츠 상품은 이 보고서의 추천 대상으로 수집하지 않는다.

태그는 상품 페이지의 실제 사용자 태그나 해당 공식 태그 필터에서 앱 ID를 검증하고 `steamTags:[{id,name}]`, `tagSourceUrl`을 기록한다. 일반 성인등급, 폭력·유혈, 공포, 개발자 콘텐츠 안내만으로 성적 태그가 있다고 판정하지 않는다. `감성적` 같은 유사 문자열도 제외한다. `mature`·`matureContent`는 보조 메타데이터일 뿐 태그 근거가 아니다. 성인 요소 탭은 기존 행을 필터링하므로 전체 수나 대표 장르의 게임 행을 복제하지 않는다. `includeMature:false`이면 해당 태그 게임과 탭을 숨긴다. 노골적인 성적 설명·이미지를 전재하지 않으며 연령 확인·로그인·지역 제한을 우회하지 않는다.

호출 예: `$steam-epic-daily-brief 장르: 로그라이크, 방치형 / 제외: 공포. 오늘 신작·할인·무료 배포를 정리해줘.`

## 조사 범위와 출처

매 실행 때 현재 날짜와 시간을 확인한다. 호스트의 현지 시간이나 과거 예시 날짜를 그대로 쓰지 않는다. 사용자가 제공한 현지 시간 정보를 우선하고, 보고서에 `기준: YYYY-MM-DD HH:mm KST / 대한민국`을 적는다.

[공식 출처와 접근 대안](references/sources.md)을 읽고 Steam에서 다음을 확인한다.

- **신작:** 기본적으로 최근 7일 출시한 본편을 조사한다. 정식 출시, 앞서 해보기, 다른 스토어에 뒤늦게 입점한 작품을 구분한다. 확정된 향후 7일 출시 예정작은 별도 표시한다. 업데이트·DLC·데모를 본편 신작으로 세지 않는다.
- **할인:** 현재 구매 가능한 본편 할인을 확인한다. 기본 우선순위는 검증된 좋은 가격, 긍정적인 이용자 평가, 한국어 지원, 마감 임박 순이다. 할인율만으로 추천하지 않고 추천 이유를 한 줄 덧붙인다.
- **무료 배포:** 기간 안에 수령하면 Steam 계정에 남는 본편 무료 증정을 가장 먼저 확인한다. 현재 배포와 공식 예고된 다음 배포를 구분한다.

목록·검색으로 후보를 찾은 뒤 선정할 게임의 공식 상품 페이지 또는 공식 공지에서 가격, 에디션, 출시일, 배포 조건과 기한을 확인한다. 검색 결과 요약과 캐시된 과거 기사만으로 현재 할인·배포를 확정하지 않는다. 한국 지역 상품 URL과 Steam app ID를 유지하고 같은 게임을 중복 집계하지 않는다.

## 판단 규칙

- 한국어 페이지라는 이유만으로 한국 지역 가격이라고 판단하지 않는다. KRW가 실제 표시되었을 때만 원화 가격을 적는다. 외화만 보이면 `한국 가격 미확인`이라고 쓰고 필요할 때만 확인된 원래 통화 가격을 병기한다. 환율로 변환한 금액을 한국 판매가로 쓰지 않는다.
- 할인은 확인된 정가·할인가·할인율·에디션을 함께 적는다. 쿠폰·리워드·구독자 혜택은 일반 결제 가격과 구분하고 적용 조건을 밝힌다. 같은 에디션·지역·혜택 조건이 확인될 때만 스토어 간 가격을 비교한다.
- `역대 최저가`는 같은 지역·통화·에디션의 가격 이력으로 검증했을 때만 사용한다. 확인하지 않았다면 현재 할인이라고만 표현한다.
- `기간 한정 무료 소장`, `무료 주말/기간 한정 플레이`, `상시 무료(F2P)`, `데모`, `DLC·인게임 보상`을 구분한다. 가격이 0원인 사실만으로 영구 소장 배포라고 판단하지 않는다. 기본 무료 배포 표에는 기간 한정 본편 무료 소장만 넣고, 다른 유형은 유용할 때 별도 한 줄로 알린다.
- 종료 시각은 원본의 날짜·시각·시간대를 확인해 KST로 변환한다. 미국 시간은 해당 날짜의 서머타임을 반영한다. 날짜만 있으면 시각을 추측하지 말고 `종료일 YYYY-MM-DD / 정확한 시각 미공개`처럼 표시한다. 정기 배포 요일을 근거로 이번 기한을 만들어내지 않는다. 종료 여부는 보고 기준 시각과 비교하고, 종료된 혜택은 현재 표에서 제외한다.
- 한국어 지원은 공식 언어 표에서 확인하고 자막·인터페이스·음성을 확인 가능한 범위에서 구분한다. 한국어 스토어 설명문만으로 한국어 지원이라고 판단하지 않는다. 평가를 쓰면 평가 출처·기간과 가능하면 표본 수를 붙인다.
- 미공개·미확인 정보는 그대로 표시한다. 취향에 대한 추천은 사실과 구분해 근거를 짧게 적는다. 사용자가 취향을 말하지 않았다면 장르를 골고루 선정한다.

## 매일 실행과 중복 처리

스킬은 한 번 호출될 때 한 번 조사한다. 예약 실행이 필요하면 호스트의 자동화 기능을 사용하며 스킬 안에서 대기 루프나 자체 스케줄러를 만들지 않는다. 요청에 예약 설정이 포함되어 있으면 사용자가 정한 시간·시간대를 자동화에 반영한다. 조사 중에 새 자동화를 반복 생성하지 않는다.

접근 가능한 직전 보고서가 있으면 스토어 ID, 에디션, 가격, 배포 기간을 비교해 `신규`, `가격 변경`, `마감 임박`, `계속 진행`을 구분한다. 변동 없는 항목은 축약하되 현재 수령 가능한 무료 소장 배포와 24시간 이내 종료 혜택은 다시 알린다. 이력이 없으면 첫 보고임을 밝히고 최근 7일 기준으로 시작한다. 미리보기 출력 파일 외에 별도 이력 저장소는 요청받았을 때 만든다. 이력에 접근할 수 없는데 어제와 비교했다고 쓰지 않는다.

## 보고서

게임명 바로 아래에 할인율과 가격을 같은 줄로 표시하고 가격을 가장 크게 강조한다. 할인율은 가격 옆 한 곳에만 표시한다. 출시 상태는 이미지 모서리의 작은 라벨로 표시한다. `releaseDate`(YYYY-MM-DD), `releaseState`(released/early_access/upcoming), `isNewRelease`, `discountPercent`, `priceValue`, `originalPriceValue`를 검증한 값으로 기록한다. **기존 출시작에는 출시일·일반 출시 배지를 표시하지 않는다. 신작 라벨은 `신작`만 표시하고 출시일은 마우스 오버 툴팁에 넣는다.** 앞서 해보기·출시 예정 상태는 짧게 표시하고 날짜는 툴팁으로 제공한다. 할인율은 가격 줄의 녹색 블록 한 곳에만 표시한다.

한국어 지원은 `koreanSupported`(true/false/null), `koreanDetails`로 기록해 `한국어 O/X/미확인` 보조 텍스트로 나눈다. 평가는 같은 출처·기간·언어 범위의 `reviewCount`, `reviewSummary`, `reviewScore`, `reviewPositivePercent`, `reviewScope`, `reviewUrl`을 사용한다. 리뷰 수는 `리뷰 500↑`, `1,000↑`, `5,000↑`, `10,000↑` 같은 단계 표시, 평가는 Steam 원래 문구(매우 긍정적·압도적으로 긍정적·복합적 등) 텍스트로 표시한다. 정확한 수·긍정률·범위는 툴팁에 넣고 최근 30일 자료면 리뷰 표시에도 `최근`을 표시한다. 최근 수와 전체 평가를 서로 섞지 않는다. 정보가 없으면 평가 없음/미확인으로 구분하고 임의 계산으로 Steam 평가 이름을 만들지 않는다.

검증한 Steam 사용자 태그는 설명 아래에 바로 표시한다. 기본 태그 3개와 확인한 성적·노출 요소 태그를 우선 노출하고 나머지는 같은 줄의 `+N`으로 펼친다. `추가 정보` 안으로 숨기지 않는다. `Steam 사용자 태그와 한국 지역 본편 가격을 확인했습니다.` 같은 조사 과정 문구는 출력하지 않는다. 실제 구매 조건만 필요할 때 `purchaseNote`로 짧게 적는다. 분량 제한은 `selectionLimits:{new:3,deals:3}`로 기록해 유형 필터에서도 장르별 최대 3개를 유지한다. 할인 필터는 별도 선정한 할인을 먼저 보여 주고 여유가 있으면 출시 할인을 보완한다.

제목·기준 시각 아래에 왼쪽 장르·태그 목록과 오른쪽 `전체·신작·할인·무료 배포` 유형 필터·게임 목록을 배치한다. 상단 할인·마감 요약, 하이라이트 목록, 반복 안내는 출력하지 않는다. 장르와 유형은 교차 적용하고 출시 할인 중인 신작은 신작·할인 양쪽에서 보여 주되 전체에서 중복하지 않는다. 확인 범위·지역·성인 요소 포함 여부·세부 참고사항은 접어서 제공한다. 아래 유형별 개수는 특정 장르 조사 기준이며 정기 보고는 앞서 정한 장르별 분량을 적용한다. [보고서 디자인](references/report-design.md)에 따라 일반 브라우저 보고서 미리보기에 게임별 공식 Steam 썸네일·게임명·가격·할인율·설명·마감·한국어·평가를 함께 표시한다. 채팅 Markdown에서 일부 썸네일이 누락되는 현상이 있어 미리보기를 우선하며, 실제 이미지 로드 상태를 확인한다. 같은 게임의 확인한 공식 이미지 대안으로 로드 실패를 보완한다. 썸네일만 별도 목록으로 출력하지 않는다. 이미지를 누르면 해당 Steam 페이지가 열리며 이미지가 안 보이더라도 가격과 설명은 유지한다. 모든 게임명에는 직접 공식 상품/공지 링크를 붙인다. 확인된 항목이 적으면 수를 억지로 채우지 않는다.

1. **무료로 받을 게임:** 게임·스토어 / 배포 유형과 수령 조건 / 수령 마감(KST) / 한국어 지원. 현재 무료 소장 배포는 기본 최대 10개, 공식 다음 배포 예고는 별도로 최대 3개다. 24시간 이내 마감은 눈에 띄게 표시한다.
2. **주목할 신작:** 장르당 최대 3개. 게임·스토어 / 출시일과 출시 상태 / 장르와 한 줄 특징 / 한국 가격 / 한국어 지원·초기 평가. 출시 예정작은 현재 출시작과 구분한다.
3. **살펴볼 할인:** 장르당 최대 3개. 게임·스토어·에디션 / 정가 → 할인가·할인율 / 종료(KST) / 추천 근거. 무료 표에 실린 동일 혜택을 중복 추천하지 않는다.
4. **확인 범위와 제한:** 스토어별로 신작·할인·무료 배포의 확인 상태를 짧게 남긴다. 조사 성공 후 조건에 맞는 결과가 없으면 `확인한 범위에서 해당 없음`, 페이지 누락·접근 실패면 `확인 불가`로 구분한다. 전수 조사라고 주장하지 않는다.

스토어 접속이 막히거나 동적 목록이 누락되면 공식 상품 페이지·공지·도메인 제한 검색을 활용한다. 일시적 오류는 한 번 재시도한 뒤 다른 공식 경로를 사용한다. 무료 게임 목록이 보이지 않는 것만으로 배포가 없다고 결론 내리지 않는다. 확인한 결과만 보고하고 누락 범위를 밝힌다. Steam 전체를 확인할 수 없으면 최신 정보를 확인하지 못했다고 짧게 보고하며 과거 가격으로 표를 채우지 않는다.


## 현재 화면 선호

- 디자인은 Steam 스토어와 가까운 **짙은 남색 바탕·청회색 보조 텍스트·파란 선택 표시**를 사용한다. 왼쪽에 장르 세로 목록과 실제 태그 체크박스를 두고, 오른쪽에 유형 필터와 게임 목록을 둔다. 장르를 작은 글씨로 상단 한 줄에 압축하지 않는다. 좁은 화면에서는 `장르 · 태그` 버튼으로 왼쪽 탐색을 펼친다.
- 왼쪽 장르는 하나씩 선택한다. 태그는 여러 개 선택할 수 있으며 **선택한 태그를 모두 포함(AND)**한 결과를 보여 준다. 장르·유형·태그를 교차 적용하고 선택한 태그 해제·전체 초기화를 제공한다. 태그는 실제 조사 자료만 사용하고 체크할 때 새 리서치를 시작하거나 상품 태그를 추측하지 않는다. **태그 검색창은 제공하지 않는다. 패널 제목은 `태그`만 표시하며 `모두 포함` 안내 문구는 생략한다.** 태그 수는 현재 장르·유형의 조사된 후보 수다. 인디는 실제 사용자 태그 또는 검증한 공식 인디 장르 정보로 판별하며 설명을 툴팁에 남긴다. 화면에서 선택한 필터는 다음 날 정기 조사 범위를 바꾸지 않는다.
- 신작 최대 3개 / 할인 최대 3개를 각각 제목이 있는 별도 구역으로 나눈다. 각 구역은 이미지가 큰 카탈로그 형태로 넓은 화면에서 3열, 중간 2열, 좁은 화면에서 1열이다. 무료 배포는 별도 구역이다. 같은 게임의 행을 복제하지 않는다.
- 게임 정보는 **큰 이미지 → 제목 → 할인율·정가·현재 가격 → 짧은 설명 → 한국어·리뷰 → 핵심 태그** 순서다. 가격이 가장 강한 글자여야 한다. 할인율은 현재 가격 바로 옆 녹색 블록에 한 번만 표시한다. 설명 아래로 가격을 내리지 않는다. 긴 설명은 2줄로 줄이고 툴팁에 전체를 보존한다.
- 큰 이미지에는 확인한 공식 `header_image` 등 실제 넓은 이미지를 `thumbnailWideUrl`에 넣는다. 없는 URL을 만들거나 작은 이미지를 새 주소로 조립하지 않는다. 기존 `thumbnailUrl`·`thumbnailAlternates`의 실패 보완은 유지한다.
- 강조 상자를 최소화한다. 신작·앞서 해보기 등은 이미지 모서리 작은 라벨과 날짜 툴팁으로 제공한다. 한국어 O는 **초록색 체크·텍스트**로 강조하되 배경 상자를 만들지 않는다. 리뷰 수·평가는 보조 텍스트로 표시하며 출처·범위·정확한 수치는 툴팁에 둔다. 조사 완료 문구는 출력하지 않는다.
- 실제 태그 중 핵심 장르·플레이 방식 2개는 약간 밝은 글씨로 구분하고, 다른 태그는 차분한 텍스트로 둔다. `primaryTags`는 실제 `steamTags`에 있는 이름만 사용한다. 기본 3개와 성적·노출 태그를 바로 보여 주며 나머지는 +N으로 펼친다. 태그마다 색상 배지를 만들지 않는다.
- 장르명은 짧고 알아보기 쉬운 이름과 작은 단색 아이콘을 쓰며 전체 이름은 title·aria-label에 보존한다. 게임명은 공식 명칭을 유지하고 한 줄 말줄임·전체 이름 툴팁으로 길이를 관리한다.
- **증분은 별도 장르**다. 현재 확인한 Steam 인크리멘탈 태그 ID는 560542이며 당일 공식 태그·상품 설명에서 확인한다. 자원·업그레이드·자동화·초월 등의 반복 성장 구조를 검증한다. 단지 레벨업이나 방치 기능만 있다는 이유로 증분으로 분류하지 않는다. 중복 게임은 대표 장르 한 곳에 선정한다.


## Steam 영상 미리보기

공식 상품 페이지나 appdetails의 실제 `movies` 데이터에서 트레일러 주소를 확인해 `videoSources:[{url,type}]`, `videoTrailerId`, `videoTitle`, `videoSourceUrl`에 기록한다. 현재 Steam 응답에는 HLS 주소만 있는 경우가 있으므로 확인하지 않은 MP4 주소를 조립하지 않는다. 실제 게임플레이 영상이 있으면 우선하고, 없으면 확인한 공식 트레일러를 사용한다. 주소를 확인하지 못하면 영상 버튼을 만들지 않고 썸네일을 유지한다.

이미지에 마우스를 350ms 이상 올리면 무음·인라인으로 재생하고 벗어나면 썸네일로 복원한다. 모바일·키보드에는 영상 재생/정지 버튼을 제공한다. 영상은 상호작용 전에는 요청하지 않고 동시에 하나만 재생한다. 필터 변경·브라우저 비활성화 시 정지하며 동작 줄이기 설정에서는 마우스 오버 자동 재생을 하지 않는다. 재생 실패·미지원은 썸네일로 복구한다.

플레이어는 브라우저의 기본 HLS를 우선하고 필요한 경우에만 템플릿에 고정한 HLS.js 1.7.4와 무결성 값을 사용한다. 미디어는 실제 공식 Steam CDN의 같은 앱 트레일러 URL에서 직접 재생한다. 영상을 내려받아 재업로드·변환·프록시로 표시하지 않는다. URL이 있다는 이유만으로 실제 재생을 확인했다고 말하지 않는다.

세부 탐색에 유용한 자동화·인크리멘탈·클리커·도시 건설·타워 디펜스·농장 시뮬레이션·생활 시뮬레이션·추리·오토 배틀러·협동 태그는 확인된 결과가 있을 때 태그 목록 위쪽에서 먼저 보여 준다. 이들은 기존 대표 장르와 교차하는 분류이며 같은 게임을 추가 행으로 복제하지 않는다.


## 추가 장르와 분리 기준

- 자동화·공장: Steam 자동화 태그(255534)를 확인하고 실제 생산 라인·가공·운송·물류·공장 운영이 핵심인지 설명으로 검증한다. 단순 자동 클릭·방치 수익만 있으면 증분·방치형에 둔다.
- 타워 디펜스: 태그(1645)와 방어 시설·유닛 배치, 몰려오는 적을 막는 플레이를 함께 확인한다. 이름에 타워가 있거나 대규모 전투가 있다는 이유만으로 넣지 않는다.
- 도시 건설: 태그(4328)와 도시·정착지의 건물·주민·자원 운영을 확인한다. 상점 하나를 운영하는 게임은 도시 건설로 분류하지 않는다.
- 덱빌딩: 태그(32322)와 카드 풀에서 덱을 구성·변경하며 플레이하는 구조를 확인한다. 카드가 등장하거나 카드를 제작만 한다는 이유로 덱빌딩에 넣지 않는다.
- 오토배틀러: 태그(1084988)와 유닛·진형·장비를 준비한 뒤 자동 전투를 치르는 구조를 확인한다. 자동 사격만 하는 게임과 구분한다.

덱빌딩과 오토배틀러는 독립 장르다. 양쪽 태그가 있어도 실제 핵심 플레이에 맞는 대표 장르 한 곳만 선정하고 중복 행을 만들지 않는다. 과거 요청·선택 상태의 `덱빌딩·자동 전투`는 두 장르의 OR 조건으로 해석한다. 각 새 장르도 신작 최대 3개·할인 최대 3개, 인디 우선·무료 소장 별도·미확인 구분 원칙을 동일하게 적용한다.
